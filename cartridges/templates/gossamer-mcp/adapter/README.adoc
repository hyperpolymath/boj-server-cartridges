= gossamer-mcp / adapter — protocol bridge
:orientation: shallow

== Purpose

Exposes this cartridge's FFI over the wire protocols declared in
`cartridge.json`. Dispatches tool invocations to the C-ABI exports at
`../ffi/` and formats responses per protocol.

This is the **template** adapter — `just mint` copies this tree — so it
carries the canonical "unified adapter" shape: **one loopback listener**,
protocol-classified (REST `/invoke`, SSE `/sse`, GraphQL `/graphql`,
gRPC-compat `/grpc/<Svc>/<Method>`), funnelling every request through the
transaction gate (`exposureSatisfied`) before a **single** dispatch into
`ffi.boj_cartridge_invoke`.

== Files

[cols="1,4"]
|===
| File | Role

| `build.zig`  | Zig build graph — depends on the sibling `ffi` target.

== Invariants

* **Internal-only, never a public ingress.** Per ADR-0004 the only governed
  public surface is the `http-capability-gateway` (tier-2); this adapter binds
  loopback (`127.0.0.1`) and sits behind it.
* **Stateless** — all state lives behind the FFI, never in the adapter.
* **Response passthrough** — whatever the FFI returns goes back to the wire
  unmodified (no embellishment, no silent recovery).
* **Cartridge.json is source of truth** for the tool catalogue; drift between
  adapter and manifest is a CI failure.

== Test/proof surface

`zig build test` runs the inline adapter tests: protocol classification,
per-protocol tool extraction, the dispatch funnel into the one Zig ABI (every
tool in `cartridge.json`), and the `exposureSatisfied` truth table.

`zig build` is the stronger gate of the two — it compiles the executable, so
`main()` and the listener path are analysed. A test-only run does not reach
them.

== Read-first

. `gossamer_adapter.zig` — dispatch function and per-protocol routers.
. `../cartridge.json` — the tool manifest the dispatcher mirrors.
